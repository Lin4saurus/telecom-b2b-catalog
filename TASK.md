- 2026-09-16 — Bug real encontrado y corregido en `QuoteForm.tsx` (M26): la usuaria corrió el SQL correctamente, pero al enviar una cotización real obtuvo "No pudimos enviar tu solicitud" en pantalla y, en la consola del navegador, `401 (Unauthorized)` / `42501 new row violates row-level security policy for table "quotes"`. Causa: mi código original encadenaba `.select("id").single()` después del `insert` en `quotes` para obtener el id y poder relacionar `quote_items` — pero pedir la fila insertada de vuelta (`RETURNING`) exige permiso de **lectura** vía RLS, y la política de `quotes` correctamente solo permite `SELECT` a usuarios autenticados (no a público anónimo), así que el insert completo quedaba rechazado aunque los datos fueran válidos. El código viejo del M7 nunca lo sufrió porque nunca pedía la fila de vuelta. **Corrección**: se genera el `id` en el cliente con `crypto.randomUUID()` (API nativa del navegador, sin dependencias nuevas) y se envía explícitamente en el insert, sin encadenar `.select()`; ese mismo id se usa después para los `quote_items`. No se tocó ninguna política de RLS ni el SQL ya ejecutado — la solución es enteramente de código, y evita a propósito la alternativa de "abrir SELECT en quotes a anon", que hubiera sido un retroceso de seguridad real (cualquiera podría leer los datos de contacto de todos los clientes). Verificado: `npm run build` y `npm run lint` sin errores. **No verificado por mí**: que el envío real ahora funcione de punta a punta — le corresponde a la usuaria repetir la prueba.
